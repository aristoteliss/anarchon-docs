Κάθε εκτέλεση καταγράφεται στο store. Οποιοδήποτε instance μπορεί να διαβάσει αυτή την εγγραφή, συμπεριλαμβανομένης μιας διεργασίας που δεν εκτελεί καθόλου εργασίες.

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
const runs = await scheduler.history('sync', 5); // οι πιο πρόσφατες πρώτα
const last = await scheduler.lastRun('sync');
const next = scheduler.nextRun('sync');
const jobs = scheduler.jobs();
```

</TabItem>
<TabItem label=".NET">

```csharp
var runs = await scheduler.HistoryAsync("sync", 5); // οι πιο πρόσφατες πρώτα
var last = await scheduler.LastRunAsync("sync");
var next = scheduler.GetNextRun("sync");
var jobs = scheduler.GetJobs();
```

</TabItem>
</Tabs>

## `history(name, limit?)`, `HistoryAsync(name, limit)`

Επιστρέφει τις πιο πρόσφατες εκτελέσεις μιας εργασίας από **όλα τα instances**, με τις νεότερες πρώτα. Το `limit` είναι από 1 έως 10000 και έχει προεπιλογή το 20.

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
for (const run of await scheduler.history('sync', 5)) {
  console.log(run.scheduledAt.toISOString(), run.instanceId, run.attempt, run.status, run.durationMs);
}
```

</TabItem>
<TabItem label=".NET">

```csharp
foreach (var run in await scheduler.HistoryAsync("sync", 5))
{
    Console.WriteLine($"{run.ScheduledAt:O} {run.InstanceId} {run.Attempt} {run.Status} {run.Duration?.TotalMilliseconds}");
}
```

</TabItem>
</Tabs>

```
2026-10-10T12:00:20.000Z api-1 1 success 198
2026-10-10T12:00:10.000Z api-3 1 success 212
2026-10-10T12:00:00.000Z api-2 1 success 205
```

Υπάρχει **μία εγγραφή ανά προσπάθεια**. Μια εκτέλεση της οποίας έγινε ανάληψη (takeover) εμφανίζεται δύο φορές: η προσπάθεια που δεν ολοκληρώθηκε και εκείνη που ολοκληρώθηκε.

```
2026-10-10T12:00:00.000Z api-2 2 success      4010     <- ένα εφεδρικό instance την ολοκλήρωσε
2026-10-10T12:00:00.000Z api-1 1 interrupted           <- ο πρώτος runner της πέθανε
```

Η ανάγνωση του ιστορικού λειτουργεί για οποιοδήποτε όνομα εργασίας, ακόμη και αν δεν έχει καταχωριστεί σε αυτό το instance, και συνδέεται αυτόνομα αν ο scheduler δεν έχει ξεκινήσει.

## Η εγγραφή εκτέλεσης

| Node.js | .NET (`RunRecord`) | Σημασία |
| --- | --- | --- |
| `job` | `Job` | Το όνομα της εργασίας |
| `slot` | `Slot` | Προγραμματισμένη ώρα, ms από το 1970 |
| `scheduledAt` | `ScheduledAt` | Το slot ως `Date` (`DateTimeOffset`) |
| `instanceId` | `InstanceId` | Ποιο instance εκτέλεσε αυτή την προσπάθεια |
| `attempt` | `Attempt` | `1`, ή `2` και άνω όταν ένα εφεδρικό ανέλαβε την εκτέλεση |
| `reason` | `Reason` | scheduled, manual, catch-up ή takeover |
| `manual` | `IsManual` | true για χειροκίνητη εκτέλεση |
| `status` | `Status` | Δείτε παρακάτω |
| `startedAt` | `StartedAt` | Πότε το instance τη διεκδίκησε και την ξεκίνησε |
| `finishedAt` | `FinishedAt` | Πότε ολοκληρώθηκε. Λείπει (`null`) όσο εκτελείται |
| `durationMs` | `Duration` (`TimeSpan?`) | Λείπει όσο εκτελείται |
| `error` | `Error` | Το μήνυμα σφάλματος, όταν η κατάσταση είναι failed |

### Κατάσταση

| Node.js | .NET (`RunStatus`) | Σημασία |
| --- | --- | --- |
| `running` | `Running` | Σε εξέλιξη |
| `success` | `Success` | Ο handler επέστρεψε |
| `failed` | `Failed` | Ο handler πέταξε σφάλμα ή έληξε το timeout |
| `interrupted` | `Interrupted` | Η προσπάθεια δεν ολοκληρώθηκε: ο runner της πέθανε ή πάγωσε, έχασε την εκτέλεση από εφεδρικό instance ή διακόπηκε |

:::note
Η κατάσταση interrupted για έναν νεκρό runner απαιτεί backend μίσθωσης, το οποίο μπορεί να αντιληφθεί ότι ο runner χάθηκε. Στα backends μόνο διεκδίκησης, μια εκτέλεση της οποίας ο runner πέθανε συνεχίζει να εμφανίζεται ως running, επειδή τίποτα δεν την ενημερώνει διαφορετικά.
:::

## `lastRun(name)`, `LastRunAsync(name)`

Η πιο πρόσφατη προσπάθεια, ή `null` αν η εργασία δεν εκτελέστηκε ποτέ.

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
const last = await scheduler.lastRun('sync');
const healthy = last?.status === 'success' && Date.now() - last.startedAt.getTime() < 60_000;
```

</TabItem>
<TabItem label=".NET">

```csharp
var last = await scheduler.LastRunAsync("sync");
var healthy = last is { Status: RunStatus.Success } && DateTimeOffset.UtcNow - last.StartedAt < TimeSpan.FromMinutes(1);
```

</TabItem>
</Tabs>

## `nextRun(name)`, `GetNextRun(name)`

Πότε αναμένεται η επόμενη εκτέλεση μιας καταχωρισμένης εργασίας, ως `Date` (`DateTimeOffset?`), ή `null` αν δεν υπάρχουν άλλες εκτελέσεις (μια εφάπαξ εργασία στο παρελθόν). Η εκτέλεση ξεκινά έως και ένα jitter αργότερα, σε όποιο instance τη διεκδικήσει.

Προκαλεί σφάλμα (throws) αν η εργασία δεν είναι καταχωρισμένη σε αυτό το instance.

## `jobs()`, `GetJobs()`

Οι εργασίες που έχουν καταχωριστεί σε αυτό το instance (εγγραφές `JobInfo` στο .NET).

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
console.table(scheduler.jobs());
```

</TabItem>
<TabItem label=".NET">

```csharp
foreach (var job in scheduler.GetJobs())
{
    Console.WriteLine($"{job.Name} {job.Type} {job.Schedule} {job.NextRunAt:O} {job.RunningHere}");
}
```

</TabItem>
</Tabs>

| name | type | schedule | nextRunAt | runningHere |
| --- | --- | --- | --- | --- |
| sync | every | every 10s | 2026-10-10T12:00:10.000Z | 0 |
| digest | cron | cron "0 8 * * 1-5" (Europe/Athens) | 2026-10-12T05:00:00.000Z | 0 |

Το `runningHere` (`RunningHere`) είναι ο αριθμός των εκτελέσεων αυτής της εργασίας που εκτελεί αυτό το instance αυτή τη στιγμή.

## Διεργασία μόνο για ανάγνωση

Ένα dashboard ή ένα admin API δεν χρειάζεται να εκτελεί εργασίες. Δημιουργήστε έναν scheduler που δείχνει στο ίδιο store, μην καταχωρίσετε καμία εργασία και απλώς διαβάστε:

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
const reader = new Scheduler({ backend: new RedisBackend({ redis: process.env.REDIS_URL, prefix: 'billing:cron:' }) });

app.get('/jobs/:name/runs', async (req, res) => {
  res.json(await reader.history(req.params.name, 50));
});
```

</TabItem>
<TabItem label=".NET">

```csharp
var reader = new Scheduler(new SchedulerOptions
{
    Backend = new RedisBackend(new RedisBackendOptions { Configuration = redisUrl, Prefix = "billing:cron:" }),
});

app.MapGet("/jobs/{name}/runs", (string name) => reader.HistoryAsync(name, 50));
```

</TabItem>
</Tabs>

Πρέπει να χρησιμοποιεί το ίδιο store και το ίδιο prefix ή table με τα instances που εκτελούν τις εργασίες.

## Έλεγχοι υγείας

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
app.get('/health/cron', async (_req, res) => {
  const last = await scheduler.lastRun('sync');
  const ageMs = last ? Date.now() - last.startedAt.getTime() : Infinity;
  const ok = last?.status !== 'failed' && ageMs < 3 * 10_000; // το "sync" εκτελείται κάθε 10 δευτ.
  res.status(ok ? 200 : 503).json({ ok, last });
});
```

</TabItem>
<TabItem label=".NET">

```csharp
// Ένας έλεγχος υγείας ASP.NET Core: builder.Services.AddHealthChecks().AddCheck<CronHealthCheck>("cron");
public sealed class CronHealthCheck(Scheduler scheduler) : IHealthCheck
{
    public async Task<HealthCheckResult> CheckHealthAsync(HealthCheckContext context, CancellationToken cancellationToken = default)
    {
        var last = await scheduler.LastRunAsync("sync", cancellationToken);
        var age = last is null ? TimeSpan.MaxValue : DateTimeOffset.UtcNow - last.StartedAt;
        var ok = last?.Status != RunStatus.Failed && age < TimeSpan.FromSeconds(30); // το "sync" εκτελείται κάθε 10 δευτ.
        return ok ? HealthCheckResult.Healthy() : HealthCheckResult.Unhealthy($"last sync: {last?.Status}, {age} ago");
    }
}
```

</TabItem>
</Tabs>

Ο έλεγχος του **store** αντί της τοπικής κατάστασης σημαίνει ότι ο έλεγχος επιτυγχάνει σε κάθε instance εφόσον κάποιο instance εκτελεί την εργασία, κάτι που είναι το επιθυμητό πίσω από έναν load balancer.

## Πόσο ιστορικό διατηρείται

Το μέγεθος του ιστορικού (`historySize`, `HistorySize`· προεπιλογή 1000 εκτελέσεις ανά εργασία) και το όριο ηλικίας (`historyTtlMs`, `HistoryTtl`· χωρίς όριο από προεπιλογή) ελέγχουν τι διατηρείται. Και τα δύο είναι [επιλογές εργασιών](../job-options/#historysize-και-historyttlms) με προεπιλογές σε επίπεδο scheduler.

Το πού αποθηκεύεται εξαρτάται από το backend:

| Backend | Πού αποθηκεύεται το ιστορικό |
| --- | --- |
| Redis / Valkey | Ένα stream διεκδικήσεων και ένα sorted set αποτελεσμάτων, ανά εργασία |
| PostgreSQL / SQLite | Ο πίνακας `<table>_attempts` |
| RabbitMQ | Μια ουρά stream ανά εργασία |
| NATS | Το JetStream stream, στα subjects της εργασίας |
