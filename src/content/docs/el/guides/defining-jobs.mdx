import { Tabs, TabItem } from '@astrojs/starlight/components';

Μια εργασία έχει ένα **όνομα**, ένα **πρόγραμμα** και έναν **handler**. Υπάρχουν τρία είδη προγραμματισμού, το καθένα με τη δική του μέθοδο. Και οι τρεις επιστρέφουν τον scheduler, επιτρέποντας την αλυσιδωτή κλήση τους (chaining).

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
scheduler
  .every('sync', '10s', syncCustomers)             // ένα μεσοδιάστημα
  .cron('digest', '0 8 * * 1-5', sendDigest)       // μια έκφραση cron
  .at('launch', '2026-12-01T09:00:00Z', announce); // μία φορά
```

</TabItem>
<TabItem label=".NET">

```csharp
scheduler
    .Every("sync", TimeSpan.FromSeconds(10), SyncCustomersAsync)                   // ένα μεσοδιάστημα
    .Cron("digest", "0 8 * * 1-5", SendDigestAsync)                                // μια έκφραση cron
    .At("launch", DateTimeOffset.Parse("2026-12-01T09:00:00Z"), AnnounceAsync);    // μία φορά
```

</TabItem>
</Tabs>

:::tip[Ο ένας κανόνας]
Καταχωρίστε τις ίδιες εργασίες, με τα ίδια ονόματα και προγράμματα, σε κάθε instance. Τα instances συμφωνούν στις ώρες εκτέλεσης επειδή τις υπολογίζουν από το ίδιο πρόγραμμα.
:::

## Εργασίες μεσοδιαστήματος: `every()`, `Every()`

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
scheduler.every(name, interval, handler, options?)
```

</TabItem>
<TabItem label=".NET">

```csharp
scheduler.Every(string name, TimeSpan interval, Func<JobContext, Task> handler, EveryJobOptions? options = null)
```

</TabItem>
</Tabs>

Στο Node.js το μεσοδιάστημα (interval) είναι ένας αριθμός χιλιοστών του δευτερολέπτου (milliseconds) ή ένα string διάρκειας. Στο .NET είναι ένα `TimeSpan`· τα attributes δέχονται τα ίδια strings διάρκειας, τα οποία διαβάζονται από το `Duration.Parse`.

| Γράφεται ως | Σημαίνει |
| --- | --- |
| `10_000` | 10 δευτερόλεπτα |
| `'10s'` | 10 δευτερόλεπτα |
| `'35m'` | 35 λεπτά |
| `'1h30m'` | 1 ώρα και 30 λεπτά |
| `'2d'` | 2 ημέρες |
| `'1.5h'` | 1 ώρα και 30 λεπτά |

Οι μονάδες μέτρησης είναι `ms`, `s`, `m`, `h` και `d`. Το μικρότερο δυνατό μεσοδιάστημα είναι 1 δευτερόλεπτο.

### Οι εκτελέσεις τοποθετούνται σε ένα σταθερό πλέγμα

Το `every('10s')` **δεν** σημαίνει «10 δευτερόλεπτα μετά την εκκίνηση της διεργασίας». Σημαίνει κάθε πολλαπλάσιο των 10 δευτερολέπτων μετρώντας από 1970-01-01 UTC: :00, :10, :20 και ούτω καθεξής.

Αυτό είναι σημαντικό για δύο λόγους:

- Κάθε instance υπολογίζει τις ίδιες χρονικές στιγμές, ανεξάρτητα από το πότε ξεκίνησε. Αυτό είναι που τους επιτρέπει να ανταγωνίζονται για την ίδια εκτέλεση.
- Μια επανεκκίνηση δεν μετατοπίζει το πρόγραμμα.

```
every('10s')   12:00:00  12:00:10  12:00:20  12:00:30
every('1h')    12:00:00  13:00:00  14:00:00
every('1d')    00:00:00 UTC κάθε μέρα
```

### Μετατόπιση του πλέγματος: `offsetMs`, `Offset`

Δύο ωριαίες εργασίες θα ξεκινούσαν και οι δύο στην αρχή της ώρας. Μια μετατόπιση (offset) μετακινεί μία από αυτές:

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
scheduler.every('rates', '1h', fetchRates);                             // 12:00, 13:00, ...
scheduler.every('invoices', '1h', buildInvoices, { offsetMs: 30 * 60_000 }); // 12:30, 13:30, ...
```

</TabItem>
<TabItem label=".NET">

```csharp
scheduler.Every("rates", TimeSpan.FromHours(1), FetchRatesAsync);                                                  // 12:00, 13:00, ...
scheduler.Every("invoices", TimeSpan.FromHours(1), BuildInvoicesAsync, new() { Offset = TimeSpan.FromMinutes(30) }); // 12:30, 13:30, ...
```

</TabItem>
</Tabs>

Το offset πρέπει να είναι το ίδιο σε κάθε instance.

:::caution
Οι εργασίες μεσοδιαστήματος λειτουργούν σε UTC. Ένα μεσοδιάστημα μίας ημέρας εκτελείται τα μεσάνυχτα UTC, όχι τα μεσάνυχτα της τοπικής σας ώρας. Για πραγματικές ώρες ρολογιού σε συγκεκριμένη ζώνη ώρας, χρησιμοποιήστε μια εργασία cron.
:::

## Εργασίες cron: `cron()`, `Cron()`

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
scheduler.cron(name, expression, handler, options?)
```

</TabItem>
<TabItem label=".NET">

```csharp
scheduler.Cron(string name, string expression, Func<JobContext, Task> handler, CronJobOptions? options = null)
```

</TabItem>
</Tabs>

Μια έκφραση cron έχει πέντε πεδία, ή έξι όταν το πρώτο πεδίο είναι δευτερόλεπτα:

```
┌──────── δευτερόλεπτο (προαιρετικό, 0-59)
│ ┌────── λεπτό (0-59)
│ │ ┌──── ώρα (0-23)
│ │ │ ┌── ημέρα του μήνα (1-31)
│ │ │ │ ┌ μήνας (1-12)
│ │ │ │ │ ┌ ημέρα της εβδομάδας (0-7, η Κυριακή είναι 0 ή 7)
* * * * * *
```

| Έκφραση | Εκτελείται |
| --- | --- |
| `0 8 * * 1-5` | 08:00, Δευτέρα έως Παρασκευή |
| `30 3 * * *` | 03:30 κάθε μέρα |
| `0 */2 * * *` | Κάθε 2 ώρες, στην αρχή της ώρας |
| `0 0 1 * *` | Μεσάνυχτα την 1η κάθε μήνα |
| `*/15 * * * * *` | Κάθε 15 δευτερόλεπτα (έξι πεδία) |

Η ανάλυση των εκφράσεων γίνεται από το [croner](https://github.com/hexagon/croner) στο Node.js και από το [Cronos](https://github.com/HangfireIO/Cronos) στο .NET. Και τα δύο διαβάζουν τις τυπικές εκφράσεις πέντε και έξι πεδίων παραπάνω με τον ίδιο τρόπο· ελέγξτε ασυνήθιστη σύνταξη (`L`, `W`, `#`) και στα δύο πριν συνδυάσετε instances Node.js και .NET στην ίδια εργασία.

### Ζώνες ώρας

Από προεπιλογή, μια έκφραση cron διαβάζεται στην τοπική ζώνη ώρας του διακομιστή. Αυτό μπορεί να διαφέρει μεταξύ των μηχανημάτων, οπότε ορίστε το ρητά:

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
// Ανά εργασία
scheduler.cron('open-market', '30 9 * * 1-5', open, { timezone: 'America/New_York' });

// Ή μία φορά για όλες τις εργασίες cron
const scheduler = new Scheduler({ timezone: 'Europe/Athens' });
```

</TabItem>
<TabItem label=".NET">

```csharp
// Ανά εργασία
scheduler.Cron("open-market", "30 9 * * 1-5", OpenAsync, new() { TimeZone = TimeZoneInfo.FindSystemTimeZoneById("America/New_York") });

// Ή μία φορά για όλες τις εργασίες cron
var scheduler = new Scheduler(new SchedulerOptions { Backend = backend, TimeZone = TimeZoneInfo.FindSystemTimeZoneById("Europe/Athens") });
```

</TabItem>
</Tabs>

Χρησιμοποιήστε ονόματα IANA όπως `Europe/Athens` ή `UTC` (στο .NET, το `TimeZoneInfo.FindSystemTimeZoneById` τα δέχεται σε κάθε πλατφόρμα). Οι αλλαγές θερινής/χειμερινής ώρας διαχειρίζονται από τη βιβλιοθήκη cron: η ώρα «08:00 ώρα Αθήνας» παραμένει 08:00 τοπική ώρα όλο το χρόνο.

## Εφάπαξ εργασίες: `at()`, `At()`

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
scheduler.at(name, when, handler, options?)
```

</TabItem>
<TabItem label=".NET">

```csharp
scheduler.At(string name, DateTimeOffset when, Func<JobContext, Task> handler, JobOptions? options = null)
```

</TabItem>
</Tabs>

Εκτελείται μία φορά, σε ένα instance. Στο Node.js το `when` είναι ένα `Date`, χιλιοστά του δευτερολέπτου από το 1970, ή ένα ISO string· στο .NET ένα `DateTimeOffset`:

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
scheduler.at('launch', '2026-12-01T09:00:00Z', announce);
scheduler.at('reminder', new Date(Date.now() + 60 * 60_000), remind); // σε μία ώρα
scheduler.at('cutover', 1796115600000, cutOver);
```

</TabItem>
<TabItem label=".NET">

```csharp
scheduler.At("launch", DateTimeOffset.Parse("2026-12-01T09:00:00Z"), AnnounceAsync);
scheduler.At("reminder", DateTimeOffset.UtcNow.AddHours(1), RemindAsync); // σε μία ώρα
scheduler.At("cutover", DateTimeOffset.FromUnixTimeMilliseconds(1796115600000), CutOverAsync);
```

</TabItem>
</Tabs>

Κάθε instance καταχωρίζει την εργασία, και ένα από αυτά την εκτελεί, όπως συμβαίνει με οποιαδήποτε άλλη εκτέλεση.

Μια εφάπαξ εργασία της οποίας η ώρα έχει ήδη παρέλθει δεν εκτελείται όταν την καταχωρίζετε, με μία εξαίρεση: σε ένα backend μίσθωσης (lease backend), αν η εκτέλεσή της αναμενόταν εντός του παραθύρου ανάκτησης (`catchUpMs`, `CatchUp`· 5 λεπτά από προεπιλογή) και κανένα instance δεν την εκτέλεσε, το πρώτο instance που θα εκκινήσει την εκτελεί. Αυτός είναι ο ίδιος κανόνας [ανάκτησης (catch-up)](../../internals/leases/#ανάκτηση-catch-up-κατά-την-εκκίνηση) όπως και για τις υπόλοιπες εργασίες.

## Ονόματα εργασιών

- Πρέπει να είναι μοναδικά μέσα σε έναν scheduler. Η καταχώριση του ίδιου ονόματος δύο φορές προκαλεί σφάλμα (throws).
- Το όνομα αποτελεί μέρος των κλειδιών ή των εγγραφών στο store. Η μετονομασία μιας εργασίας ξεκινά ένα νέο ιστορικό.
- Στο RabbitMQ και στο NATS, τα ονόματα επιτρέπεται να περιέχουν μόνο γράμματα, ψηφία, `_` και `-`, επειδή μετατρέπονται σε ονόματα ουρών (queue names) και subjects.

## Προσθήκη και αφαίρεση εργασιών κατά τον χρόνο εκτέλεσης

Οι εργασίες μπορούν να προστεθούν πριν ή μετά την εκκίνηση του scheduler.

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
await scheduler.start();
scheduler.every('late-addition', '1m', work); // προγραμματίζεται αμέσως
```

</TabItem>
<TabItem label=".NET">

```csharp
await scheduler.StartAsync();
scheduler.Every("late-addition", TimeSpan.FromMinutes(1), WorkAsync); // προγραμματίζεται αμέσως
```

</TabItem>
</Tabs>

Η μέθοδος `remove(name)` (`Remove(name)` στο .NET) σταματά τον προγραμματισμό μιας εργασίας σε αυτό το instance. Επιστρέφει `false` αν δεν υπάρχει τέτοια εργασία.

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
scheduler.remove('sync');
scheduler.every('sync', '30s', syncCustomers); // το ίδιο όνομα με νέο πρόγραμμα
```

</TabItem>
<TabItem label=".NET">

```csharp
scheduler.Remove("sync");
scheduler.Every("sync", TimeSpan.FromSeconds(30), SyncCustomersAsync); // το ίδιο όνομα με νέο πρόγραμμα
```

</TabItem>
</Tabs>

Η αφαίρεση μιας εργασίας επηρεάζει μόνο αυτό το instance. Τα υπόλοιπα instances συνεχίζουν να την εκτελούν, το ιστορικό της διατηρείται, και μια εκτέλεση που βρίσκεται ήδη σε εξέλιξη εδώ ολοκληρώνεται κανονικά.

:::caution
Κατά τη διάρκεια ενός rolling deploy που αλλάζει ένα πρόγραμμα, τα παλιά και τα νέα instances διαφωνούν προσωρινά ως προς τις ώρες εκτέλεσης. Το καθένα υπολογίζει τα δικά του χρονικά διαστήματα (slots), οπότε για εκείνη τη στιγμή είναι ενεργά και τα δύο προγράμματα. Αν αυτό έχει σημασία για την εφαρμογή σας, αναπτύξτε την αλλαγή σε ένα ενιαίο βήμα ή χρησιμοποιήστε ένα νέο όνομα εργασίας.
:::

## Επιλογή μεταξύ `every()` και `cron()`

| Θέλετε | Χρησιμοποιήστε |
| --- | --- |
| «Κάθε N δευτερόλεπτα/λεπτά/ώρες», η ώρα της ημέρας δεν έχει σημασία | `every()`, `Every()` |
| Μια συγκεκριμένη ώρα ρολογιού, καθημερινές ή συγκεκριμένη ζώνη ώρας | `cron()`, `Cron()` |
| Κάτι που συμβαίνει μία μόνο φορά | `at()`, `At()` |
