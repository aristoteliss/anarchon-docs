Ένα backend είναι μια κλάση που υλοποιεί το interface `Backend` (`IBackend` στο .NET, στο namespace `Anarchon.Backends`). Αν τα instances σας μοιράζονται ένα store που μπορεί να πραγματοποιήσει μία ατομική λειτουργία «εγγραφή εκτός αν υπάρχει ήδη», μπορείτε να γράψετε ένα δικό σας.

## Το συμβόλαιο (The contract)

Ένας κανόνας έχει μεγαλύτερη σημασία από οτιδήποτε άλλο:

> Για μία εργασία και ένα slot, η μέθοδος `claim()` (`ClaimAsync()`) επιστρέφει `true` για **ακριβώς ένα** instance.

Ο scheduler αναλαμβάνει τα υπόλοιπα: υπολογίζει τα slots, περιμένει το jitter, καλεί το `claim()`, εκτελεί τον handler στον νικητή και αποθηκεύει το αποτέλεσμα.

<TabItem label="Node.js">

```ts
interface Backend {
  /** Εμφανίζεται ως scheduler.backend.name, π.χ. 'memory'. */
  readonly name: string;
  /** Για πόσο χρόνο το store απομνημονεύει μια δεσμευμένη εκτέλεση (ms). Infinity αν είναι για πάντα. */
  readonly dedupeWindowMs: number;

  /** Σύνδεση και έλεγχος του server. Καλείται από το start() και πριν από αναγνώσεις. */
  init(): Promise<void>;
  /** Ρύθμιση μίας φοράς για μια εργασία: δημιουργία του πίνακα, του stream ή της ουράς της. */
  prepareJob(job: string, historySize: number): Promise<void>;
  /** True για ακριβώς ένα instance ανά slot. Πρέπει να είναι ασφαλές να επαναληφθεί με το ίδιο token. */
  claim(input: ClaimInput): Promise<boolean>;
  /** Καταγραφή εκτέλεσης από runNow(). Χωρίς deduplication. */
  recordManualRun(input: ClaimInput): Promise<number | void>;
  /** Αποθήκευση του πώς ολοκληρώθηκε μια εκτέλεση. */
  saveResult(job: string, result: StoredResult, historySize: number, historyTtlMs?: number): Promise<void>;
  /** Πρόσφατες εκτελέσεις από όλα τα instances, οι νεότερες πρώτα. */
  history(job: string, limit: number): Promise<RunRecord[]>;
  /** Κλείσιμο όσων άνοιξε το ίδιο το backend. */
  close(): Promise<void>;

  /** Προαιρετικό: απόρριψη εργασίας που αυτό το backend δεν μπορεί να εκτελέσει με ασφάλεια. Πετάξτε σφάλμα (throw) για απόρριψη. */
  checkJob?(job: JobLimits): void;
  /** Προαιρετικό: καλείται μετά από ένα κερδισμένο claim, αν το claim() δεν αποτελεί ήδη εγγραφή ιστορικού. */
  recordClaim?(input: ClaimInput): Promise<void>;
  /** Προαιρετικό: παρόν σε backends με μισθώσεις (leases). */
  readonly runs?: RunStore;
}
```

public interface IBackend
{
    /// <summary>Εμφανίζεται ως scheduler.Backend.Name, π.χ. "memory".</summary>
    string Name { get; }
    /// <summary>Για πόσο χρόνο το store απομνημονεύει μια δεσμευμένη εκτέλεση. TimeSpan.MaxValue αν είναι για πάντα.</summary>
    TimeSpan DedupeWindow { get; }
    /// <summary>Παρόν σε backends με μισθώσεις (leases).</summary>
    IRunStore? Runs => null;

    /// <summary>Προαιρετικό: απόρριψη εργασίας που αυτό το backend δεν μπορεί να εκτελέσει με ασφάλεια. Πετάξτε εξαίρεση (throw) για απόρριψη.</summary>
    void CheckJob(JobLimits job) { }
    /// <summary>Σύνδεση και έλεγχος του server. Καλείται από το StartAsync() και πριν από αναγνώσεις.</summary>
    Task InitAsync(CancellationToken cancellationToken);
    /// <summary>Ρύθμιση μίας φοράς για μια εργασία: δημιουργία του πίνακα, του stream ή της ουράς της.</summary>
    Task PrepareJobAsync(string job, int historySize, CancellationToken cancellationToken);
    /// <summary>True για ακριβώς ένα instance ανά slot. Πρέπει να είναι ασφαλές να επαναληφθεί με το ίδιο token.</summary>
    Task<bool> ClaimAsync(ClaimInput input, CancellationToken cancellationToken);
    /// <summary>Προαιρετικό: καλείται μετά από ένα κερδισμένο claim, αν το ClaimAsync() δεν αποτελεί ήδη εγγραφή ιστορικού.</summary>
    Task RecordClaimAsync(ClaimInput input, CancellationToken cancellationToken) => Task.CompletedTask;
    /// <summary>Καταγραφή εκτέλεσης από RunNowAsync(). Χωρίς deduplication.</summary>
    Task<long?> RecordManualRunAsync(ClaimInput input, CancellationToken cancellationToken);
    /// <summary>Αποθήκευση του πώς ολοκληρώθηκε μια εκτέλεση.</summary>
    Task SaveResultAsync(string job, StoredResult result, int historySize, TimeSpan? historyTtl, CancellationToken cancellationToken);
    /// <summary>Πρόσφατες εκτελέσεις από όλα τα instances, οι νεότερες πρώτα.</summary>
    Task<IReadOnlyList<RunRecord>> HistoryAsync(string job, int limit, CancellationToken cancellationToken);
    /// <summary>Κλείσιμο όσων άνοιξε το ίδιο το backend.</summary>
    Task CloseAsync();
}

Το `ClaimInput` είναι αυτό που στέλνει ένα instance:

| Πεδίο (Node.js, .NET) | Σημασία |
| --- | --- |
| `job`, `Job` | Το όνομα της εργασίας |
| `slot`, `Slot` | Ο προγραμματισμένος χρόνος σε Unix ms: μαζί με το `job`, η ταυτότητα της εκτέλεσης |
| `token`, `Token` | Μια τυχαία τιμή μοναδική για αυτή την προσπάθεια |
| `instanceId`, `InstanceId` | Ποιος υποβάλλει το αίτημα |
| `historySize`, `historyTtlMs`· `HistorySize`, `HistoryTtl` | Πόσο ιστορικό να διατηρείται |

## Ένα πλήρες παράδειγμα

Αυτό το backend διατηρεί τα πάντα στη μνήμη. Συντονίζει schedulers μόνο στην **ίδια διεργασία**, γεγονός που το καθιστά χρήσιμο για unit tests και για την κατανόηση του συμβολαίου στην πιο απλή του μορφή.

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
import { type Backend, buildHistory, type ClaimInput, type ClaimRecord, type RunRecord, type StoredResult } from 'anarchon';

export class MemoryBackend implements Backend {
  readonly name = 'memory';
  /** Τα claims δεν ξεχνιούνται ποτέ εδώ, επομένως δεν υπάρχει όριο στο πόσο καθυστερημένο μπορεί να είναι ένα instance. */
  readonly dedupeWindowMs = Infinity;

  private readonly claims = new Map<string, ClaimRecord & { job: string; token: string }>();
  private readonly results = new Map<string, StoredResult[]>();

  async init(): Promise<void> {}
  async prepareJob(): Promise<void> {}
  async close(): Promise<void> {}

  /** Το μοναδικό βήμα που πρέπει να είναι ατομικό. Εδώ είναι, επειδή η JavaScript το εκτελεί χωρίς διακοπή (single-threaded event loop). */
  async claim(input: ClaimInput): Promise<boolean> {
    const key = `${input.job}|${input.slot}`;
    const existing = this.claims.get(key);
    if (existing) return existing.token === input.token; // το ίδιο claim που στάλθηκε ξανά εξακολουθεί να είναι δικό μας
    this.claims.set(key, { job: input.job, token: input.token, slot: input.slot, by: input.instanceId, at: Date.now(), manual: false });
    return true;
  }

  async recordManualRun(input: ClaimInput): Promise<undefined> {
    const claim = { job: input.job, token: input.token, slot: input.slot, by: input.instanceId, at: Date.now(), manual: true };
    this.claims.set(`${input.job}|${input.slot}|manual`, claim);
    return undefined; // χρησιμοποιείται το slot που ζητήθηκε
  }

  async saveResult(job: string, result: StoredResult): Promise<void> {
    this.results.set(job, [...(this.results.get(job) ?? []), result]);
  }

  async history(job: string, limit: number): Promise<RunRecord[]> {
    const claims = [...this.claims.values()].filter((claim) => claim.job === job);
    return buildHistory({ job, claims, results: this.results.get(job) ?? [], limit });
  }
}
```

```csharp
using System.Collections.Concurrent;
using Anarchon;
using Anarchon.Backends;

public sealed class MemoryBackend : IBackend
{
    private readonly ConcurrentDictionary<(string Job, long Slot), ClaimInput> _claims = new();
    private readonly ConcurrentQueue<(ClaimInput Input, DateTimeOffset At)> _manual = new();
    private readonly ConcurrentDictionary<string, ConcurrentQueue<StoredResult>> _results = new();
    private readonly ConcurrentDictionary<(string Job, long Slot), DateTimeOffset> _claimedAt = new();

    public string Name => "memory";

    /// <summary>Τα claims δεν ξεχνιούνται ποτέ εδώ, επομένως δεν υπάρχει όριο στο πόσο καθυστερημένο μπορεί να είναι ένα instance.</summary>
    public TimeSpan DedupeWindow => TimeSpan.MaxValue;

    public Task InitAsync(CancellationToken cancellationToken) => Task.CompletedTask;

    public Task PrepareJobAsync(string job, int historySize, CancellationToken cancellationToken) => Task.CompletedTask;

    public Task CloseAsync() => Task.CompletedTask;

    /// <summary>Το μοναδικό βήμα που πρέπει να είναι ατομικό. Εδώ είναι, επειδή το GetOrAdd κρατά την πρώτη τιμή για ένα κλειδί.</summary>
    public Task<bool> ClaimAsync(ClaimInput input, CancellationToken cancellationToken)
    {
        var first = _claims.GetOrAdd((input.Job, input.Slot), input);
        _claimedAt.TryAdd((input.Job, input.Slot), DateTimeOffset.UtcNow);
        return Task.FromResult(first.Token == input.Token); // το ίδιο claim που στάλθηκε ξανά εξακολουθεί να είναι δικό μας
    }

    public Task<long?> RecordManualRunAsync(ClaimInput input, CancellationToken cancellationToken)
    {
        _manual.Enqueue((input, DateTimeOffset.UtcNow));
        return Task.FromResult<long?>(null); // χρησιμοποιείται το slot που ζητήθηκε
    }

    public Task SaveResultAsync(string job, StoredResult result, int historySize, TimeSpan? historyTtl, CancellationToken cancellationToken)
    {
        _results.GetOrAdd(job, _ => new()).Enqueue(result);
        return Task.CompletedTask;
    }

    public Task<IReadOnlyList<RunRecord>> HistoryAsync(string job, int limit, CancellationToken cancellationToken)
    {
        var claims = _claims.Values.Where(c => c.Job == job)
            .Select(c => new ClaimRecord { Slot = c.Slot, By = c.InstanceId, At = _claimedAt[(c.Job, c.Slot)] })
            .Concat(_manual.Where(m => m.Input.Job == job)
                .Select(m => new ClaimRecord { Slot = m.Input.Slot, By = m.Input.InstanceId, At = m.At, IsManual = true }));
        var results = _results.TryGetValue(job, out var saved) ? saved.ToArray() : [];
        return Task.FromResult(RunHistory.Build(job, claims, results, limit));
    }
}
```

## Το ατομικό βήμα σε ένα πραγματικό store

Στη μνήμη, το `claim()` είναι ατομικό εκ των πραγμάτων (στο .NET, μέσω του `ConcurrentDictionary.GetOrAdd`). Σε ένα κοινόχρηστο store, ο έλεγχος και η εγγραφή πρέπει να είναι **μία ενιαία λειτουργία στον server**. Ο έλεγχος πρώτα και η εγγραφή μετά, ως δύο ξεχωριστές κλήσεις, είναι το κλασικό σφάλμα:

```mermaid
sequenceDiagram
  participant A as Instance A
  participant B as Instance B
  participant S as Store
  Note over A,S: Λάθος: δύο ξεχωριστές κλήσεις
  A->>S: είναι δεσμευμένη η εκτέλεση 12:00:10;
  S-->>A: όχι
  B->>S: είναι δεσμευμένη η εκτέλεση 12:00:10;
  S-->>B: όχι
  A->>S: σημείωσέ την ως δεσμευμένη
  B->>S: σημείωσέ την ως δεσμευμένη
  Note over A,B: και τα δύο εκτελούν την εργασία
```

Χρησιμοποιήστε ό,τι προσφέρει το store σας για να το κάνετε σε ένα βήμα:

| Δυνατότητα του store | Παράδειγμα |
| --- | --- |
| Εισαγωγή με μοναδικό κλειδί (unique key) | `INSERT ... ON CONFLICT DO NOTHING`, και έπειτα έλεγχος αν εισήχθη γραμμή |
| Εγγραφή υπό συνθήκη (conditional write) | «put if absent», compare-and-set |
| Script στον server ή transaction | Redis Lua scripts, SQL transactions |
| Δημοσίευση με αποδιπλασιασμό (de-duplicated publish) | NATS message IDs, περιορισμένη ουρά με απόρριψη (rejection) |

## Κάντε το `claim()` ασφαλές για επανάληψη

Οι clients δικτύου κάνουν επαναπροσπάθειες (retries). Αν σταλεί ένα claim, η σύνδεση πέσει, και ο client το στείλει ξανά, η δεύτερη κλήση πρέπει να απαντήσει και πάλι `true` για το instance που έχει ήδη κερδίσει. Για αυτό υπάρχει το `token`: αποθηκεύστε το μαζί με το claim, και όταν φτάσει ένα claim για ένα ήδη δεσμευμένο slot, συγκρίνετε τα tokens.

## `dedupeWindowMs`

Για πόσο χρόνο το store σας απομνημονεύει μια δεσμευμένη εκτέλεση (`DedupeWindow` στο .NET). Αν την απομνημονεύει για πάντα, επιστρέψτε `Infinity` (`TimeSpan.MaxValue`).

Αν την ξεχνά μετά από κάποιο διάστημα (ένα TTL, ένα bounded stream), επιστρέψτε εκείνο το χρονικό διάστημα. Ο scheduler στη συνέχεια απορρίπτει οποιαδήποτε εργασία της οποίας το `jitterMs + maxLateMs` δεν είναι μικρότερο, επειδή ένα instance που θα έφτανε αργότερα από τη μνήμη του store θα μπορούσε να εκτελέσει ξανά την εργασία.

## Προσθήκη μισθώσεων (leases)

Ένα backend που παρέχει επίσης το `runs`, ένα `RunStore` (`Runs`, ένα `IRunStore`, στο .NET), αποκτά εφεδρικούς (backups), προστασία επικάλυψης (overlap protection), ανάκτηση (catch-up) και παράδοση (hand-over). Διαθέτει πέντε μεθόδους:

| Μέθοδος | Τι πρέπει να κάνει, ατομικά |
| --- | --- |
| `claim(input)`, `ClaimAsync` | Να αποφασίσει μεταξύ των `won`, `running`, `done`, `overlap`, `none` και `late` βάσει της αποθηκευμένης κατάστασης της εκτέλεσης (στο .NET, τα records `ClaimOutcome`) |
| `heartbeat(job, slot, token, leaseMs)`, `HeartbeatAsync` | Να παρατείνει τη λήξη της μίσθωσης **μόνο αν** το αποθηκευμένο token ταιριάζει |
| `finish(job, slot, token, status)`, `FinishAsync` | Να σημειώσει την εκτέλεση ως ολοκληρωμένη, μόνο με το αντίστοιχο token |
| `release(job, slot, token)`, `ReleaseAsync` | Να τερματίσει μια ενεργή μίσθωση άμεσα ώστε να αναλάβει ένας εφεδρικός (ομαλός τερματισμός) |
| `active(job)`, `ActiveAsync` | Να απαριθμήσει τις μη ολοκληρωμένες εκτελέσεις και αν κάθε μίσθωση είναι ενεργή |

Οι κανόνες είναι οι ίδιοι σε κάθε lease backend, και το [Μισθώσεις](../../internals/leases/) τους περιγράφει με ακρίβεια. Αν το store σας υποστηρίζει SQL, δεν χρειάζεται να τους γράψετε από την αρχή. Στο Node.js, τα `PostgresBackend` και `SqliteBackend` δέχονται έναν adapter με δύο συναρτήσεις, και υλοποιούν τις μισθώσεις πάνω σε αυτόν. Στο .NET, επεκτείνετε το `SqlBackend`, όπως δείχνει η επόμενη ενότητα.

```ts
import { SqliteBackend } from 'anarchon';

// Οποιοσδήποτε client με all() και transaction() λειτουργεί με τα SQL backends
const backend = new SqliteBackend({
  database: {
    all: (sql, params) => myDriver.query(sql, params),
    transaction: (fn) => myDriver.transaction((tx) => fn({ all: (sql, params) => tx.query(sql, params) })),
  },
});
```

## Μια άλλη βάση SQL

Για μια βάση SQL, επεκτείνετε το `SqlBackend` αντί να γράψετε το συμβόλαιο μόνοι σας (στο .NET, από το πακέτο `Anarchon.Sql`): φέρνει τους πίνακες, τη συναλλαγή διεκδίκησης, τις μισθώσεις και το ιστορικό. Εσείς δίνετε τη σύνδεση, έναν έλεγχο του server, και ένα `SqlDialect`: ό,τι διαφέρει από βάση σε βάση (ο τύπος ακεραίων, το ρολόι του server, το κλείδωμα γραμμών, τα placeholders). Στο .NET η σύνδεση είναι οποιοδήποτε `DbConnection` του ADO.NET, και το dialect είναι μια κλάση στην οποία ορίζετε τα `BigInt` και `NowMs`, και κάνετε override τα `ForUpdate`, `SerializeClaims`, `ExtraTables`, `BeginClaimAsync` και `IsAlreadyCreated` όταν χρειάζεται.

```ts
import { fromSqliteDatabase, SqlBackend, type SqlClient, type SqlDialect } from 'anarchon';

class EmbeddedSqlBackend extends SqlBackend {
  readonly name = 'embedded-sql';
  protected readonly dialect: SqlDialect = {
    bigint: 'INTEGER',
    nowMs: `CAST(ROUND((julianday('now') - 2440587.5) * 86400000.0) AS INTEGER)`,
    forUpdate: '',
    placeholders: (sql) => sql,
    extraTables: () => [],
    serialize: async () => {},
    isAlreadyCreated: () => false,
  };

  constructor() {
    super('embedded_runs');
  }

  protected async connect(): Promise<{ client: SqlClient; owned: boolean }> {
    return { client: fromSqliteDatabase(openDatabase()), owned: true };
  }

  protected async checkServer(): Promise<void> {}
}
```

## Δοκιμή ενός backend

Ανεξάρτητα από το store, ελέγξτε το συμβόλαιο απευθείας:

1. **Ο αγώνας δρόμου (The race).** Στείλτε το ίδιο claim από πολλαπλούς clients ταυτόχρονα, πολλές φορές. Ακριβώς ένας πρέπει να κερδίζει κάθε φορά.
2. **Ασφάλεια επανάληψης (Repeat safety).** Το νικητήριο claim όταν αποσταλεί ξανά, με το ίδιο token, απαντά και πάλι `true`. Ένα διαφορετικό token απαντά `false`.
3. **Ιστορικό.** Ένα claim συν ένα αποθηκευμένο αποτέλεσμα επιστρέφεται από το `history()` (`HistoryAsync()`) ως μία εγγραφή με το σωστό instance και status.

Το `backendContract()` από το `anarchon/testing` εκτελεί αυτούς τους τρεις ελέγχους στο backend σας, σε οποιονδήποτε test runner. Δώστε του μια συνάρτηση που δημιουργεί το backend ενός instance για ένα namespace: τα backends που δημιουργούνται με το ίδιο namespace πρέπει να μοιράζονται ένα store, όπως τα instances μιας υπηρεσίας. Η σουίτα δοκιμών του ίδιου του anarchon εκτελεί τους ίδιους ελέγχους σε κάθε ενσωματωμένο backend.

```ts
import { backendContract } from 'anarchon/testing';
import { test } from 'vitest';

const cases = backendContract((namespace) => new MyBackend({ url: process.env.STORE_URL, prefix: `${namespace}:` }));
for (const { name, run } of cases) test(name, run, 30_000);
```

Εκτελέστε τους στο πραγματικό store, όπου οι κλήσεις επικαλύπτονται πραγματικά: ένας αγώνας σε mock δεν αποδεικνύει τίποτα. Ένας έλεγχος που αποτυγχάνει απορρίπτεται με σφάλμα `ANARCHON_CONTRACT` που λέει τι αναμενόταν και τι επέστρεψε. Το `RunStore` ενός backend μίσθωσης (ανάληψη, heartbeats, παράδοση) χρειάζεται δικές του δοκιμές.

Στο .NET οι ίδιοι έλεγχοι βρίσκονται στο `BackendContract` στο project [`test/Anarchon.Specification`](https://github.com/aristoteliss/anarchon-dotnet/tree/main/test/Anarchon.Specification), το οποίο χρησιμοποιούν οι δοκιμές κάθε ενσωματωμένου backend. Δεν δημοσιεύεται ως πακέτο· αντιγράψτε το στο test project σας, ή κάντε αναφορά στο αποθετήριο (repository).

## Συμβατότητα

Ένα backend που γράφετε συνεχίζει να λειτουργεί σε όλες τις minor εκδόσεις του anarchon:

- **Τα νέα μέλη των `Backend` και `RunStore` είναι προαιρετικά** (στο .NET, default interface methods). Ο scheduler έχει εναλλακτική λύση για backend χωρίς αυτά, οπότε η κλάση σας μεταγλωττίζεται και τρέχει χωρίς αλλαγές. Υποχρεωτικό μέλος προστίθεται μόνο σε major έκδοση.
- **Τα νέα πεδία όσων λαμβάνετε είναι προαιρετικά να διαβαστούν.** Τα `ClaimInput`, `RunClaim` και `JobLimits` μπορεί να αποκτήσουν πεδία· ένα backend που τα αγνοεί συνεχίζει να λειτουργεί.
- **Τα νέα πεδία όσων επιστρέφετε είναι προαιρετικά.** Φτιάξτε το `history()` με το `buildHistory()` (`RunHistory.Build()` στο .NET), και οι εγγραφές αποκτούν νέα πεδία χωρίς αλλαγές από την πλευρά σας.
- **Το `ClaimOutcome` μπορεί να αποκτήσει νέα είδη.** Επιστρέφετε τα είδη που γνωρίζετε· ο scheduler χειρίζεται ένα άγνωστο είδος όπως το `'done'`.
- **Τα σφάλματα που ρίχνετε** φτάνουν στον χρήστη όπως είναι. Δώστε τους δικό σας `code` αν οι καλούντες πρέπει να τα ξεχωρίζουν.

Ό,τι αποθηκεύει το backend σας είναι δική σας ευθύνη να μένει συμβατό: σε ένα rolling deploy, δύο εκδόσεις του backend σας μπορεί να μοιράζονται το store.
