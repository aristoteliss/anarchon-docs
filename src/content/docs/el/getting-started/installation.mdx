Το anarchon διατίθεται ως το πακέτο `anarchon` στο npm (Node.js 20 ή νεότερο) και ως τα πακέτα `Anarchon` στο NuGet (.NET 10). Επιλέξτε τη γλώσσα σας· η καρτέλα που επιλέγετε διατηρείται σε κάθε σελίδα.

<Tabs syncKey="language">
<TabItem label="Node.js">

Εγκαταστήστε το anarchon και τον driver για το store σας. Οι drivers είναι προαιρετικά peer dependencies, επομένως εγκαθιστάτε μόνο αυτόν που χρησιμοποιείτε.

<Tabs syncKey="backend">
  <TabItem label="Redis / Valkey">
    ```sh
    pnpm add anarchon redis
    ```
    Λειτουργεί με Redis 5 ή νεότερο και με Valkey. Το `redis` (node-redis) χρειάζεται μόνο αν το anarchon ανοίγει τη
    σύνδεση για εσάς. Μπορείτε να περάσετε έναν client που διαθέτει ήδη η εφαρμογή σας: ioredis, iovalkey,
    node-redis ή Valkey GLIDE.
  </TabItem>
  <TabItem label="PostgreSQL">
    ```sh
    pnpm add anarchon pg
    ```
    PostgreSQL 9.5 ή νεότερο. Μπορείτε να περάσετε το δικό σας `pg` Pool ή Client, ή ένα `postgres.js`
    instance, αντί για ένα connection string.
  </TabItem>
  <TabItem label="SQLite">
    ```sh
    pnpm add anarchon
    ```
    Δεν χρειάζεται τίποτα άλλο στο Node 22.13 ή νεότερο, το οποίο περιλαμβάνει ενσωματωμένο το `node:sqlite`. Το Node 22.5 έως 22.12 χρειάζεται το flag `--experimental-sqlite`. Στο Node 20 προσθέστε το `better-sqlite3@12`: η έκδοση 13 απαιτεί Node 22.
    Για έναν libSQL server ή Turso προσθέστε το `@libsql/client`.
    SQLite 3.35 ή νεότερο.
  </TabItem>
  <TabItem label="RabbitMQ">
    ```sh
    pnpm add anarchon amqplib
    ```
    RabbitMQ 3.9 ή νεότερο.
  </TabItem>
  <TabItem label="NATS">
    ```sh
    pnpm add anarchon @nats-io/transport-node @nats-io/jetstream
    pnpm add @nats-io/kv   # μόνο για strategy: 'lease'
    ```
    Το JetStream πρέπει να είναι ενεργοποιημένο στον server· η στρατηγική `lease` απαιτεί nats-server 2.10 ή νεότερο.
  </TabItem>
</Tabs>

Οι εντολές `npm install` και `yarn add` λειτουργούν με τον ίδιο τρόπο.

</TabItem>

Κάθε store αποτελεί ξεχωριστό πακέτο, το οποίο φέρνει μαζί του το `Anarchon` (τον πυρήνα) και τον driver του store.

  <TabItem label="Redis / Valkey">
    ```sh
    dotnet add package Anarchon.Redis
    ```
    Redis 5 ή νεότερο, ή Valkey, μέσω του StackExchange.Redis. Μπορείτε να περάσετε ένα `IConnectionMultiplexer` που διαθέτει ήδη η εφαρμογή σας.
  </TabItem>
  <TabItem label="PostgreSQL">
    ```sh
    dotnet add package Anarchon.Postgres
    ```
    PostgreSQL 9.5 ή νεότερο, μέσω του Npgsql. Μπορείτε να περάσετε το `NpgsqlDataSource` της εφαρμογής σας αντί για ένα connection string.
  </TabItem>
  <TabItem label="SQLite">
    ```sh
    dotnet add package Anarchon.Sqlite
    ```
    Το Microsoft.Data.Sqlite φέρνει μαζί του την SQLite (απαιτείται η 3.24 ή νεότερη). Τα libSQL και Turso είναι διαθέσιμα μόνο για Node.js.
  </TabItem>
  <TabItem label="RabbitMQ">
    ```sh
    dotnet add package Anarchon.RabbitMQ
    ```
    RabbitMQ 3.9 ή νεότερο, μέσω του RabbitMQ.Client 7.
  </TabItem>
  <TabItem label="NATS">
    ```sh
    dotnet add package Anarchon.Nats
    ```
    Το JetStream πρέπει να είναι ενεργοποιημένο στον server· το `NatsStrategy.Lease` απαιτεί nats-server 2.10 ή νεότερο.
  </TabItem>

`UseSqlite()`, `UseRabbitMQ()` ή `UseNats()` περιλαμβάνονται σε αυτά τα πακέτα: δείτε το
[ASP.NET Core](../../recipes/aspnet-core/).

## Ποιο store να επιλέξω;

Χρησιμοποιήστε αυτό που διαθέτει ήδη η υπηρεσία σας. Αν έχετε επιλογή:

| Έχετε | Χρήση | Γιατί |
| --- | --- | --- |
| Redis ή Valkey | Την προεπιλογή, στρατηγική `lease` | Το πλήρες σύνολο δυνατοτήτων και η χαμηλότερη καθυστέρηση (latency) |
| PostgreSQL, χωρίς Redis | `PostgresBackend` | Το πλήρες σύνολο δυνατοτήτων, χωρίς νέα υποδομή |
| Ένα μηχάνημα, πολλαπλές διεργασίες | `SqliteBackend` σε αρχείο | Κανένας server απολύτως |
| Μόνο NATS | `NatsBackend` με τη στρατηγική μίσθωσης (`strategy: 'lease'`, `NatsStrategy.Lease`) | Το πλήρες σύνολο δυνατοτήτων, σε ένα key-value bucket του JetStream |
| Μόνο RabbitMQ | `RabbitMQBackend` | Ένας νικητής ανά εκτέλεση, αλλά χωρίς backups, προστασία επικάλυψης ή ανάκτηση (catch-up) |

Η [Επισκόπηση backends](../../backends/overview/) τα συγκρίνει αναλυτικά.

## TypeScript

Μόνο για Node.js: το anarchon είναι γραμμένο σε TypeScript και παρέχει τους δικούς του τύπους. Δεν χρειάζεται να εγκαταστήσετε τίποτα επιπλέον.

```ts
import { Scheduler, type JobContext, type RunRecord } from 'anarchon';
```

Λειτουργεί επίσης από απλή JavaScript, με `require` ή `import`:

```js
const { Scheduler } = require('anarchon');
```

## Έλεγχος ότι λειτουργεί

Χρησιμοποιεί ένα αρχείο SQLite, επομένως δεν χρειάζεται server.

<Tabs syncKey="language">
<TabItem label="Node.js">

Αποθηκεύστε αυτό ως `check.mjs` και εκτελέστε `node check.mjs` (Node 22.13 ή νεότερο).

```js
import { Scheduler, SqliteBackend } from 'anarchon';

const scheduler = new Scheduler({ backend: new SqliteBackend({ database: './anarchon.db' }) });
scheduler.every('hello', '2s', (ctx) => console.log('hello at', ctx.scheduledAt.toISOString()));

await scheduler.start();
setTimeout(() => scheduler.stop(), 7_000);
```

</TabItem>
<TabItem label=".NET">

Σε ένα console project με το `Anarchon.Sqlite`, βάλτε αυτό στο `Program.cs` και εκτελέστε `dotnet run`.

```csharp
using Anarchon;
using Anarchon.Sqlite;

await using var scheduler = new Scheduler(new SchedulerOptions { Backend = new SqliteBackend("Data Source=anarchon.db") });
scheduler.Every("hello", TimeSpan.FromSeconds(2), ctx =>
{
    Console.WriteLine($"hello at {ctx.ScheduledAt:O}");
    return Task.CompletedTask;
});

await scheduler.StartAsync();
await Task.Delay(TimeSpan.FromSeconds(7));
await scheduler.StopAsync();
```

</TabItem>
</Tabs>

Θα πρέπει να δείτε μία γραμμή κάθε δύο δευτερόλεπτα, και στη συνέχεια η διεργασία τερματίζεται.
