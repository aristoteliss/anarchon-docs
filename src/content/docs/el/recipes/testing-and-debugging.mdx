## Δοκιμή ενός handler

Ένας handler είναι μια συνάρτηση. Οι πιο χρήσιμες δοκιμές τον καλούν απευθείας με ένα context που κατασκευάζετε εσείς. Δεν εμπλέκεται κανένας scheduler.

Στο .NET μόνο ο scheduler δημιουργεί ένα `JobContext`, επομένως αφήστε τον handler να μεταβιβάσει ό,τι χρησιμοποιεί (το slot, την προσπάθεια, το token) σε μια μέθοδο που μπορείτε να καλέσετε από μια δοκιμή.

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
import { test } from 'node:test';
import assert from 'node:assert/strict';
import type { JobContext } from 'anarchon';
import { buildInvoices } from './invoices';

function context(overrides: Partial<JobContext> = {}): JobContext {
  const slot = Date.UTC(2026, 9, 1, 6); // 2026-10-01T06:00:00Z
  return {
    name: 'monthly-invoices',
    slot,
    scheduledAt: new Date(slot),
    instanceId: 'test',
    manual: false,
    attempt: 1,
    reason: 'scheduled',
    signal: new AbortController().signal,
    ...overrides,
  };
}

test('running twice for the same slot creates each invoice once', async () => {
  await buildInvoices(context());
  await buildInvoices(context({ attempt: 2, reason: 'takeover' }));
  assert.equal(await countInvoices(), 3);
});

test('stops when the signal aborts', async () => {
  const controller = new AbortController();
  const run = buildInvoices(context({ signal: controller.signal }));
  controller.abort();
  await assert.rejects(run, { name: 'AbortError' });
});
```

</TabItem>
<TabItem label=".NET">

```csharp
// Η εργασία: ένας λεπτός handler γύρω από μια μέθοδο που παίρνει ό,τι χρειάζεται
public sealed class InvoiceJobs(Invoices invoices)
{
    [Cron("0 6 1 * *", Name = "monthly-invoices")]
    public Task BuildAsync(JobContext ctx) => invoices.BuildAsync(ctx.ScheduledAt, ctx.CancellationToken);
}

// Οι δοκιμές (xUnit)
public sealed class InvoiceTests
{
    private static readonly DateTimeOffset Slot = new(2026, 10, 1, 6, 0, 0, TimeSpan.Zero);

    [Fact]
    public async Task running_twice_for_the_same_slot_creates_each_invoice_once()
    {
        var invoices = new Invoices(TestDatabase.Create());
        await invoices.BuildAsync(Slot, CancellationToken.None);
        await invoices.BuildAsync(Slot, CancellationToken.None); // προσπάθεια 2, μετά από ανάληψη (takeover)
        Assert.Equal(3, await invoices.CountAsync());
    }

    [Fact]
    public async Task stops_when_the_token_is_cancelled()
    {
        using var cancelled = new CancellationTokenSource();
        await cancelled.CancelAsync();
        await Assert.ThrowsAnyAsync<OperationCanceledException>(() => new Invoices(TestDatabase.Create()).BuildAsync(Slot, cancelled.Token));
    }
}
```

</TabItem>
</Tabs>

Αυτές οι δύο δοκιμές καλύπτουν τα δύο πράγματα που οφείλει ένας handler στον scheduler: να είναι ασφαλής στην εκτέλεση δύο φορές (idempotent), και να σταματά όταν του ζητηθεί.

## Δοκιμές με πραγματικό scheduler

Για να δοκιμάσετε τη συνδεσμολογία (wiring), χρησιμοποιήστε το `SqliteBackend` σε ένα προσωρινό αρχείο. Δεν απαιτεί server και συμπεριφέρεται όπως τα production lease backends.

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
import { mkdtempSync } from 'node:fs';
import { tmpdir } from 'node:os';
import { join } from 'node:path';
import { Scheduler, SqliteBackend } from 'anarchon';

function testScheduler(instanceId = 'test') {
  const file = join(mkdtempSync(join(tmpdir(), 'cron-test-')), 'jobs.db');
  return new Scheduler({
    backend: new SqliteBackend({ database: file }),
    instanceId,
    unrefTimers: true, // μην κρατάτε τη δοκιμαστική διεργασία ενεργή
  });
}
```

</TabItem>
<TabItem label=".NET">

```csharp
using Anarchon;
using Anarchon.Sqlite;

static string TestFile() => Path.Combine(Directory.CreateTempSubdirectory("cron-test-").FullName, "jobs.db");

static Scheduler TestScheduler(string instanceId = "test", string? file = null) => new(new SchedulerOptions
{
    Backend = new SqliteBackend($"Data Source={file ?? TestFile()}"),
    InstanceId = instanceId,
});
```

</TabItem>
</Tabs>

### Εκτέλεση μιας εργασίας χωρίς αναμονή για το πρόγραμμά της

Η μέθοδος `runNow()` (`RunNowAsync()`) εκτελεί την εργασία αμέσως και επιστρέφει την εγγραφή της:

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
test('the sync job succeeds', async () => {
  const scheduler = testScheduler();
  scheduler.every('sync', '1h', syncCustomers, { catchUpMs: 0 });
  await scheduler.start();
  try {
    const run = await scheduler.runNow('sync');
    assert.equal(run.status, 'success');
  } finally {
    await scheduler.stop();
  }
});
```

</TabItem>
<TabItem label=".NET">

```csharp
[Fact]
public async Task the_sync_job_succeeds()
{
    await using var scheduler = TestScheduler(); // σταματά στο τέλος της δοκιμής
    scheduler.Every("sync", TimeSpan.FromHours(1), SyncCustomersAsync, new() { CatchUp = TimeSpan.Zero });
    await scheduler.StartAsync();

    var run = await scheduler.RunNowAsync("sync");

    Assert.Equal(RunStatus.Success, run.Status);
}
```

</TabItem>
</Tabs>

Το `catchUpMs: 0` (`CatchUp = TimeSpan.Zero`) αποτρέπει τον scheduler από το να εκτελέσει επίσης το πιο πρόσφατο slot κατά την εκκίνηση, κάτι που διαφορετικά θα πρόσθετε μια εκτέλεση που δεν ζητήσατε.

### Δύο instances

Για να διαπιστώσετε ότι μια εκτέλεση πραγματοποιείται μία φορά, μοιράστε το αρχείο ανάμεσα σε δύο schedulers:

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
test('two instances, one run per slot', async () => {
  const file = join(mkdtempSync(join(tmpdir(), 'cron-test-')), 'jobs.db');
  const ran: string[] = [];
  const instances = ['A', 'B'].map(
    (instanceId) => new Scheduler({ backend: new SqliteBackend({ database: file }), instanceId, unrefTimers: true }),
  );
  for (const scheduler of instances) {
    scheduler.every('tick', '1s', (ctx) => void ran.push(`${ctx.slot}`), { catchUpMs: 0 });
  }
  await Promise.all(instances.map((s) => s.start()));
  await new Promise((resolve) => setTimeout(resolve, 3_500));
  await Promise.all(instances.map((s) => s.stop()));

  assert.equal(new Set(ran).size, ran.length, 'no slot ran twice');
});
```

</TabItem>
<TabItem label=".NET">

```csharp
[Fact]
public async Task two_instances_one_run_per_slot()
{
    var file = TestFile();
    var ran = new ConcurrentQueue<long>();
    var instances = new[] { "A", "B" }.Select(id => TestScheduler(id, file)).ToList();
    foreach (var scheduler in instances)
    {
        scheduler.Every("tick", TimeSpan.FromSeconds(1), ctx =>
        {
            ran.Enqueue(ctx.Slot);
            return Task.CompletedTask;
        }, new() { CatchUp = TimeSpan.Zero });
    }

    await Task.WhenAll(instances.Select(s => s.StartAsync()));
    await Task.Delay(3_500);
    await Task.WhenAll(instances.Select(s => s.StopAsync()));

    Assert.Equal(ran.Count, ran.Distinct().Count()); // κανένα slot δεν εκτελέστηκε δύο φορές
}
```

</TabItem>
</Tabs>

### Η επικύρωση ελέγχεται κατά την καταχώριση

Οι μη έγκυρες επιλογές πετούν σφάλμα (throw) κατά την προσθήκη της εργασίας, επομένως είναι εύκολο να ελεγχθούν χωρίς να ξεκινήσετε τίποτα:

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
test('refuses a jitter longer than half the interval', () => {
  const scheduler = testScheduler();
  assert.throws(() => scheduler.every('bad', '2s', () => {}, { jitterMs: 1_500 }), RangeError);
});
```

</TabItem>
<TabItem label=".NET">

```csharp
[Fact]
public async Task refuses_a_jitter_longer_than_half_the_interval()
{
    await using var scheduler = TestScheduler();
    Assert.Throws<ArgumentOutOfRangeException>(() =>
        scheduler.Every("bad", TimeSpan.FromSeconds(2), _ => Task.CompletedTask, new() { Jitter = TimeSpan.FromMilliseconds(1_500) }));
}
```

</TabItem>
</Tabs>

## Μην κάνετε mock το ρολόι γύρω από ένα πραγματικό backend

Τα εικονικά χρονόμετρα (fake timers) μετακινούν το ρολόι της διεργασίας σας, αλλά το store διατηρεί το δικό του. Σε ένα lease backend, η λήξη της μίσθωσης καθορίζεται από την ώρα του store, επομένως η μετακίνηση ενός εικονικού ρολογιού κατά μία ώρα δεν λήγει τη μίσθωση, και η δοκιμή καταλήγει να ελέγχει κάτι που δεν μπορεί να συμβεί στην πραγματικότητα. Δοκιμάστε τους handlers με ένα εικονικό context, και δοκιμάστε τη συνδεσμολογία με το `runNow()` και μικρά πραγματικά διαστήματα (intervals). Στο .NET αυτό ισχύει και για το `SchedulerOptions.TimeProvider`: ένας `FakeTimeProvider` μετακινεί τα χρονόμετρα του scheduler, όχι το ρολόι του store.

## Αποσφαλμάτωση μιας εκτέλεσης

Το αποθετήριο περιλαμβάνει παραδείγματα φτιαγμένα για debugger. Από ένα αντίγραφο του αποθετηρίου (checkout):

<Tabs syncKey="language">
<TabItem label="Node.js">

```sh
pnpm install
npx tsx examples/walkthrough.ts
```

</TabItem>
<TabItem label=".NET">

```sh
git clone https://github.com/aristoteliss/anarchon-dotnet && cd anarchon-dotnet
dotnet run --project examples/Walkthrough
```

</TabItem>
</Tabs>

Το `examples/walkthrough.ts` (`examples/Walkthrough` στο .NET) εκτελεί δύο instances σε μία διεργασία χρησιμοποιώντας ένα αρχείο SQLite, με μίσθωση 10 λεπτών και όριο καθυστέρησης (lateness limit), ώστε η παραμονή σε ένα breakpoint να μην αλλάζει το αποτέλεσμα. Η κεφαλίδα του απαριθμεί τις συναρτήσεις από τις οποίες διέρχεται μια εκτέλεση, με τη σειρά.

Στο VS Code, ανοίξτε το **Run and Debug**, επιλέξτε **Example: walkthrough (βηματική εκτέλεση μιας διαδρομής (step through one run))** και πατήστε F5. Κάνει παύση ακριβώς πριν από το `start()`. Προχωρήστε βήμα-βήμα (step in) με F11, ή ορίστε breakpoints στις παρακάτω συναρτήσεις. Το αποθετήριο .NET διαθέτει την ίδια επιλογή εκκίνησης (**Example: Walkthrough**), η οποία σταματά στο `Debugger.Break()`· η κεφαλίδα του απαριθμεί τις μεθόδους C#, όπως `JobTimers.Arm()`, `LeaseRunner.RunAsync()` και `Executor.ExecuteAsync()`.

| Αρχείο κάτω από το `src/scheduler/` | Συνάρτηση | Τι συμβαίνει εκεί |
| --- | --- | --- |
| `timers.ts` | `arm()` | Υπολογίζεται το επόμενο slot και τίθεται ένα timer |
| `scheduler.ts` | `fire()` | Το timer ενεργοποιήθηκε: η εκτέλεση είναι έτοιμη |
| `lease-runner.ts` | `run()` | Στέλνεται η διεκδίκηση (claim) και διαχειρίζεται το αποτέλεσμά της |
| `lease-runner.ts` | `executeLeased()` | Ξεκινά το heartbeat |
| `executor.ts` | `execute()` | Καλείται ο handler σας, και αποθηκεύεται το αποτέλεσμα |
| `lease-runner.ts` | `watch()` | Ένα εφεδρικό instance προγραμματίζει τον επόμενο έλεγχό του |

:::caution
Ένας debugger σε παύση σταματά το ρολόι της διεργασίας σας αλλά όχι του store. Με κανονικούς χρόνους μίσθωσης, η παύση σε ένα breakpoint για διάστημα μεγαλύτερο από το `leaseMs` (`Lease`) αναγκάζει ένα εφεδρικό (backup) instance να αναλάβει την εκτέλεση (takeover). Αυτό είναι η βιβλιοθήκη που λειτουργεί σωστά· αυξήστε το όσο κάνετε debug.
:::

Ενεργοποιήστε το ενσωματωμένο log όσο ερευνάτε:

</TabItem>
<TabItem label=".NET">

## Συνηθισμένες εκπλήξεις

| Τι βλέπετε | Γιατί |
| --- | --- |
| Μια εκτέλεση ξεκινά αμέσως μετά το `start()` με αιτία `catch-up` | Το πιο πρόσφατο slot έπρεπε να είχε εκτελεστεί πρόσφατα και κανείς δεν το εκτέλεσε. Ορίστε `catchUpMs: 0` (`CatchUp = TimeSpan.Zero`) για να το απενεργοποιήσετε |
| Κάθε instance εκτός από ένα καταγράφει `skipped (taken)` | Αυτό είναι φυσιολογικό: ένας νικητής ανά εκτέλεση |
| `skipped (overlap)` | Η προηγούμενη εκτέλεση αυτής της εργασίας συνεχίζεται ακόμη |
| Μια εκτέλεση εμφανίζεται δύο φορές στο ιστορικό | Μία εγγραφή ανά προσπάθεια: έγινε ανάληψη (taken over) |
| Μια εργασία εκτελείται στο ίδιο instance κάθε φορά | Το `jitterMs` είναι 0, ή το ρολόι αυτού του instance προηγείται |
| Συμβάντα `lost` | Το instance δεν μπόρεσε να ανανεώσει τη μίσθωσή του εγκαίρως: τέθηκε σε παύση, μπλοκαρίστηκε ή αποκόπηκε από το store |
