Every run is recorded in the store. Any instance can read that record, including a process that doesn't run jobs at all.

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
const runs = await scheduler.history('sync', 5); // newest first
const last = await scheduler.lastRun('sync');
const next = scheduler.nextRun('sync');
const jobs = scheduler.jobs();
```

</TabItem>
<TabItem label=".NET">

```csharp
var runs = await scheduler.HistoryAsync("sync", 5); // newest first
var last = await scheduler.LastRunAsync("sync");
var next = scheduler.GetNextRun("sync");
var jobs = scheduler.GetJobs();
```

</TabItem>
</Tabs>

## `history(name, limit?)`, `HistoryAsync(name, limit)`

Returns the latest runs of a job from **all instances**, newest first. `limit` is 1 to 10000 and defaults to 20.

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
for (const run of await scheduler.history('sync', 5)) {
  console.log(run.scheduledAt.toISOString(), run.instanceId, run.attempt, run.status, run.durationMs);
}
```

</TabItem>
<TabItem label=".NET">

```csharp
foreach (var run in await scheduler.HistoryAsync("sync", 5))
{
    Console.WriteLine($"{run.ScheduledAt:O} {run.InstanceId} {run.Attempt} {run.Status} {run.Duration?.TotalMilliseconds}");
}
```

</TabItem>
</Tabs>

```
2026-10-10T12:00:20.000Z api-1 1 success 198
2026-10-10T12:00:10.000Z api-3 1 success 212
2026-10-10T12:00:00.000Z api-2 1 success 205
```

There is **one record per attempt**. A run that was taken over shows twice: the attempt that didn't finish, and the one that did.

```
2026-10-10T12:00:00.000Z api-2 2 success      4010     <- a backup finished it
2026-10-10T12:00:00.000Z api-1 1 interrupted           <- its first runner died
```

Reading history works for any job name, even one not registered on this instance, and connects on its own if the scheduler hasn't started.

## The run record

| Node.js | .NET (`RunRecord`) | Meaning |
| --- | --- | --- |
| `job` | `Job` | The job's name |
| `slot` | `Slot` | Scheduled time, ms since 1970 |
| `scheduledAt` | `ScheduledAt` | The slot as a `Date` (`DateTimeOffset`) |
| `instanceId` | `InstanceId` | Who ran this attempt |
| `attempt` | `Attempt` | `1`, or `2` and up when a backup took over |
| `reason` | `Reason` | scheduled, manual, catch-up or takeover |
| `manual` | `IsManual` | true for a manual run |
| `status` | `Status` | See below |
| `startedAt` | `StartedAt` | When the instance claimed and started it |
| `finishedAt` | `FinishedAt` | When it ended. Missing (`null`) while it runs |
| `durationMs` | `Duration` (`TimeSpan?`) | Missing while it runs |
| `error` | `Error` | The error message, when the status is failed |

### Status

| Node.js | .NET (`RunStatus`) | Meaning |
| --- | --- | --- |
| `running` | `Running` | In progress |
| `success` | `Success` | The handler returned |
| `failed` | `Failed` | The handler threw or timed out |
| `interrupted` | `Interrupted` | The attempt didn't finish: its runner died or froze, lost the run to a backup, or was stopped |

:::note
Interrupted for a dead runner needs a lease backend, which can tell that the runner is gone. On claim-only backends a run whose runner died keeps showing running, because nothing ever marks it otherwise.
:::

## `lastRun(name)`, `LastRunAsync(name)`

The most recent attempt, or `null` if the job never ran.

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
const last = await scheduler.lastRun('sync');
const healthy = last?.status === 'success' && Date.now() - last.startedAt.getTime() < 60_000;
```

</TabItem>
<TabItem label=".NET">

```csharp
var last = await scheduler.LastRunAsync("sync");
var healthy = last is { Status: RunStatus.Success } && DateTimeOffset.UtcNow - last.StartedAt < TimeSpan.FromMinutes(1);
```

</TabItem>
</Tabs>

## `nextRun(name)`, `GetNextRun(name)`

When a registered job is next due, as a `Date` (`DateTimeOffset?`), or `null` if there are no more runs (a one-off job in the past). The run starts up to one jitter later, on whichever instance claims it.

It throws if the job isn't registered on this instance.

## `jobs()`, `GetJobs()`

The jobs registered on this instance (`JobInfo` records in .NET).

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
console.table(scheduler.jobs());
```

</TabItem>
<TabItem label=".NET">

```csharp
foreach (var job in scheduler.GetJobs())
{
    Console.WriteLine($"{job.Name} {job.Type} {job.Schedule} {job.NextRunAt:O} {job.RunningHere}");
}
```

</TabItem>
</Tabs>

| name | type | schedule | nextRunAt | runningHere |
| --- | --- | --- | --- | --- |
| sync | every | every 10s | 2026-10-10T12:00:10.000Z | 0 |
| digest | cron | cron "0 8 * * 1-5" (Europe/Athens) | 2026-10-12T05:00:00.000Z | 0 |

`runningHere` (`RunningHere`) is how many runs of that job this instance is executing right now.

## A read-only process

A dashboard or admin API doesn't have to run jobs. Create a scheduler pointing at the same store, register nothing, and read:

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
const reader = new Scheduler({ backend: new RedisBackend({ redis: process.env.REDIS_URL, prefix: 'billing:cron:' }) });

app.get('/jobs/:name/runs', async (req, res) => {
  res.json(await reader.history(req.params.name, 50));
});
```

</TabItem>
<TabItem label=".NET">

```csharp
var reader = new Scheduler(new SchedulerOptions
{
    Backend = new RedisBackend(new RedisBackendOptions { Configuration = redisUrl, Prefix = "billing:cron:" }),
});

app.MapGet("/jobs/{name}/runs", (string name) => reader.HistoryAsync(name, 50));
```

</TabItem>
</Tabs>

It must use the same store, and the same prefix or table, as the instances that run the jobs.

## Health checks

<Tabs syncKey="language">
<TabItem label="Node.js">

```ts
app.get('/health/cron', async (_req, res) => {
  const last = await scheduler.lastRun('sync');
  const ageMs = last ? Date.now() - last.startedAt.getTime() : Infinity;
  const ok = last?.status !== 'failed' && ageMs < 3 * 10_000; // "sync" runs every 10 s
  res.status(ok ? 200 : 503).json({ ok, last });
});
```

</TabItem>
<TabItem label=".NET">

```csharp
// An ASP.NET Core health check: builder.Services.AddHealthChecks().AddCheck<CronHealthCheck>("cron");
public sealed class CronHealthCheck(Scheduler scheduler) : IHealthCheck
{
    public async Task<HealthCheckResult> CheckHealthAsync(HealthCheckContext context, CancellationToken cancellationToken = default)
    {
        var last = await scheduler.LastRunAsync("sync", cancellationToken);
        var age = last is null ? TimeSpan.MaxValue : DateTimeOffset.UtcNow - last.StartedAt;
        var ok = last?.Status != RunStatus.Failed && age < TimeSpan.FromSeconds(30); // "sync" runs every 10 s
        return ok ? HealthCheckResult.Healthy() : HealthCheckResult.Unhealthy($"last sync: {last?.Status}, {age} ago");
    }
}
```

</TabItem>
</Tabs>

Checking the **store** rather than local state means the check passes on every instance as long as some instance is running the job, which is what you want behind a load balancer.

## How much is kept

The history size (`historySize`, `HistorySize`; default 1000 runs per job) and age limit (`historyTtlMs`, `HistoryTtl`; no limit by default) control what is kept. Both are [job options](../job-options/#historysize-and-historyttlms) with scheduler-wide defaults.

Where it is kept depends on the backend:

| Backend | Where history lives |
| --- | --- |
| Redis / Valkey | A stream of claims and a sorted set of results, per job |
| PostgreSQL / SQLite | The `<table>_attempts` table |
| RabbitMQ | A stream queue per job |
| NATS | The JetStream stream, on the job's subjects |
