anarchon comes as the `anarchon` package on npm (Node.js 20 or newer) and as the `Anarchon` packages on NuGet (.NET 10). Pick your language; the tab you pick holds for every page.

<Tabs syncKey="language">
<TabItem label="Node.js">

Install anarchon and the driver for your store. Drivers are optional peer dependencies, so you only install the one you use.

<Tabs syncKey="backend">
  <TabItem label="Redis / Valkey">
    ```sh
    pnpm add anarchon redis
    ```
    Works with Redis 5 or newer and with Valkey. `redis` (node-redis) is only needed if anarchon opens the
    connection for you. You can pass a client your app already has instead: ioredis, iovalkey,
    node-redis or Valkey GLIDE.
  </TabItem>
  <TabItem label="PostgreSQL">
    ```sh
    pnpm add anarchon pg
    ```
    PostgreSQL 9.5 or newer. You can pass your own `pg` Pool or Client, or a `postgres.js`
    instance, instead of a connection string.
  </TabItem>
  <TabItem label="SQLite">
    ```sh
    pnpm add anarchon
    ```
    Nothing else is needed on Node 22.13 or newer, which has `node:sqlite` built in. Node 22.5 to
    22.12 need the `--experimental-sqlite` flag. On Node 20 add `better-sqlite3@12`: version 13
    needs Node 22. For a libSQL server or Turso add `@libsql/client`.
    SQLite 3.35 or newer.
  </TabItem>
  <TabItem label="RabbitMQ">
    ```sh
    pnpm add anarchon amqplib
    ```
    RabbitMQ 3.9 or newer.
  </TabItem>
  <TabItem label="NATS">
    ```sh
    pnpm add anarchon @nats-io/transport-node @nats-io/jetstream
    pnpm add @nats-io/kv   # only for strategy: 'lease'
    ```
    JetStream must be enabled on the server; the `lease` strategy needs nats-server 2.10 or newer.
  </TabItem>
</Tabs>

`npm install` and `yarn add` work the same way.

</TabItem>
<TabItem label=".NET">

Each store is a package of its own, which brings in `Anarchon` (the core) and the store's driver.

<Tabs syncKey="backend">
  <TabItem label="Redis / Valkey">
    ```sh
    dotnet add package Anarchon.Redis
    ```
    Redis 5 or newer, or Valkey, on StackExchange.Redis. You can pass an `IConnectionMultiplexer` your app already has.
  </TabItem>
  <TabItem label="PostgreSQL">
    ```sh
    dotnet add package Anarchon.Postgres
    ```
    PostgreSQL 9.5 or newer, on Npgsql. You can pass your app's `NpgsqlDataSource` instead of a connection string.
  </TabItem>
  <TabItem label="SQLite">
    ```sh
    dotnet add package Anarchon.Sqlite
    ```
    Microsoft.Data.Sqlite brings SQLite with it (3.24 or newer is needed). libSQL and Turso are Node.js only.
  </TabItem>
  <TabItem label="RabbitMQ">
    ```sh
    dotnet add package Anarchon.RabbitMQ
    ```
    RabbitMQ 3.9 or newer, on RabbitMQ.Client 7.
  </TabItem>
  <TabItem label="NATS">
    ```sh
    dotnet add package Anarchon.Nats
    ```
    JetStream must be enabled on the server; `NatsStrategy.Lease` needs nats-server 2.10 or newer.
  </TabItem>
</Tabs>

With a host (ASP.NET Core, a worker service), `AddAnarchon()` and `UseRedis()`, `UsePostgres()`,
`UseSqlite()`, `UseRabbitMQ()` or `UseNats()` come with these packages: see
[ASP.NET Core](../../recipes/aspnet-core/).

</TabItem>
</Tabs>

## Which store should I pick?

Use the one your service already has. If you have a choice:

| You have | Use | Why |
| --- | --- | --- |
| Redis or Valkey | The default, `lease` strategy | The full feature set, and the least latency |
| PostgreSQL, no Redis | `PostgresBackend` | The full feature set, with no new infrastructure |
| One machine, several processes | `SqliteBackend` on a file | No server at all |
| Only NATS | `NatsBackend` with its lease strategy (`strategy: 'lease'`, `NatsStrategy.Lease`) | The full feature set, on a JetStream key-value bucket |
| Only RabbitMQ | `RabbitMQBackend` | One winner per run, but no backups, overlap protection or catch-up |

[Backends overview](../../backends/overview/) compares them in detail.

## TypeScript

Node.js only: anarchon is written in TypeScript and ships its own types. There is nothing extra to install.

```ts
import { Scheduler, type JobContext, type RunRecord } from 'anarchon';
```

It also works from plain JavaScript, with `require` or `import`:

```js
const { Scheduler } = require('anarchon');
```

## Check that it works

It uses a SQLite file, so it needs no server.

<Tabs syncKey="language">
<TabItem label="Node.js">

Save this as `check.mjs` and run `node check.mjs` (Node 22.13 or newer).

```js
import { Scheduler, SqliteBackend } from 'anarchon';

const scheduler = new Scheduler({ backend: new SqliteBackend({ database: './anarchon.db' }) });
scheduler.every('hello', '2s', (ctx) => console.log('hello at', ctx.scheduledAt.toISOString()));

await scheduler.start();
setTimeout(() => scheduler.stop(), 7_000);
```

</TabItem>
<TabItem label=".NET">

In a console project with `Anarchon.Sqlite`, put this in `Program.cs` and run `dotnet run`.

```csharp
using Anarchon;
using Anarchon.Sqlite;

await using var scheduler = new Scheduler(new SchedulerOptions { Backend = new SqliteBackend("Data Source=anarchon.db") });
scheduler.Every("hello", TimeSpan.FromSeconds(2), ctx =>
{
    Console.WriteLine($"hello at {ctx.ScheduledAt:O}");
    return Task.CompletedTask;
});

await scheduler.StartAsync();
await Task.Delay(TimeSpan.FromSeconds(7));
await scheduler.StopAsync();
```

</TabItem>
</Tabs>

You should see a line every two seconds, then the process exits.
